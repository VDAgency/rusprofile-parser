# ТЗ. Справочник ОКВЭД с «живым» поиском и пресет под сувенирную продукцию

> Документ — техническое задание на доработку модуля парсинга Rusprofile.
> Цель — заменить сырое поле «ОКВЭД» в Mini App на полноценный поиск
> по человекочитаемым описаниям с возможностью выбрать готовый набор
> «целевых» кодов под сувенирную продукцию.
>
> **Статус:** согласовано, в реализации.
> **Автор черновика:** Claude (Opus 4.7).
> **Заказчик внутри проекта:** клиент сувенирной продукции (см. CLAUDE.md).
> **Дата согласования:** 2026-05-06.

---

## 1. Цели и контекст

### 1.1 Что есть сейчас

В Mini App (`src/webapp/index.html`, `src/webapp/app.js`) поле ОКВЭД —
это обычный текстовый input с подсказкой *«Напр. 46.90 — можно несколько
через запятую»*. Пользователь обязан **знать коды наизусть**:

* Если он пишет код вида `46.90` — всё работает (бэкенд кладёт массив
  кодов в `body["okved"]`, см. `src/rusprofile/filters.py:319-325`).
* Если он пишет слово вида `торговля` — это слово уходит на Rusprofile
  как код, сервер не находит совпадения, парсер возвращает 0 компаний.

Реальный поиск ОКВЭД на самом сайте Rusprofile — это live-search с
подсказками: пользователь печатает «торговля» и сайт сам подбирает
коды. У нас этой подсказки нет.

### 1.2 Чего хотим

1. **Поиск по «живым» словам.** Пользователь печатает «продукты
   питания» / «оптовая торговля одеждой» / «реклама и маркетинг» —
   видит список подходящих кодов с описаниями и галочками, выбирает
   нужные.
2. **Иерархия и группы.** Если выбрал класс (например, `46` — оптовая
   торговля), можно одной галкой включить все подгруппы (`46.11`, `46.12`
   и т. д.).
3. **Готовый пресет «под сувенирку».** Кнопка/чекбокс «Целевые виды
   деятельности (сувенирка)» — добавляет курируемый набор кодов,
   подобранный заказчиком, одним кликом.
4. **Пайплайн остаётся прежним.** Выбранные коды кладутся в массив,
   массив уходит в существующий бэкенд (`SearchFilters.okved`), Rusprofile
   возвращает компании, как и раньше, мы пишем их в Google Sheets.

### 1.3 Что НЕ входит в это ТЗ

* ИИ-квалификация компаний по сайтам (этап 2 роадмапа, отдельная задача).
* Доп. источники данных кроме Rusprofile/Яндекс Карт (этап 3).
* Изменение логики авторизации на Rusprofile, формы Яндекс Карт,
  схемы листов Google Sheets.

## 2. Архитектурные решения

### 2.1 Источник справочника ОКВЭД-2

**Берём:** официальный классификатор ОК 029-2014 (КДЕС Ред. 2),
действующая редакция.

**Откуда:** разовая выгрузка с публичных классификаторов
(`classifikators.ru/okved` или аналог) либо XML/CSV с сайта
Минэкономразвития. Скачиваем один раз, кладём в репозиторий, в
дальнейшем подменяем при официальных правках классификатора (раз в
несколько лет).

**Объём:** ~2 500 записей, иерархия:

```
Раздел  G  (буква)            — Торговля оптовая и розничная
 Класс    46                  — Торговля оптовая, кроме автотранспорта
  Подкласс 46.3               — Торговля оптовая пищевыми продуктами
   Группа   46.39             — Торговля оптовая неспециализированная
   ...
```

### 2.2 «Живые» описания — генерируем сами без GPT

**Решение:** GPT-обогащение **не используем**. Описания и ключевые
слова для каждого кода составляет Claude (Opus 4.7) разово, в момент
подготовки справочника, на основе знаний об ОКВЭД-2.

**Почему так:**
* Нет рантайм-зависимости от платного API в проде.
* Не нужен лишний `OPENAI_API_KEY` для этой задачи (он понадобится
  только на этапе 2 роадмапа — квалификация компаний по сайтам).
* Стабильный детерминированный результат: словарь — обычный JSON в
  репозитории, версионируется git'ом, ревьюится глазами.

**Что готовится для каждого кода:**
* `description` — 1–2 предложения «живым» языком: чем реально
  занимаются такие компании, что они продают / производят / делают,
  типичные примеры. Например для `46.39`:
  > «Оптовая торговля едой и напитками без специализации — компании,
  > поставляющие магазинам и кафе сразу разные продукты: бакалею,
  > молочку, напитки, кондитерку.»
* `keywords` — массив ключевых слов и синонимов для поиска: формы
  слов, отраслевой жаргон, бытовые названия. Пример:
  `["продукты", "продукты питания", "еда", "опт продуктов", "бакалея",
  "продуктовый дистрибьютор"]`.

### 2.3 Структура хранения данных

Новый каталог `data/okved/`:

```
data/okved/
├── okved_raw.json          — сырой справочник (только официальное)
├── okved_enriched.json     — он же + description + keywords (рабочий файл)
├── okved_targets.json      — курируемый пресет «под сувенирку»
└── README.md               — формат, как обновлять
```

**Схема `okved_enriched.json`** (массив объектов):

```json
{
  "code": "46.39",
  "name": "Торговля оптовая неспециализированная пищевыми продуктами, напитками и табачными изделиями",
  "level": 4,
  "parent": "46.3",
  "section": "G",
  "section_name": "Торговля оптовая и розничная",
  "is_leaf": false,
  "description": "Оптовая торговля едой и напитками без специализации — компании, поставляющие магазинам и кафе сразу разные продукты.",
  "keywords": ["продукты", "продукты питания", "еда", "опт продуктов", "бакалея"]
}
```

* `level` — 1 (раздел), 2 (класс), 3 (подкласс), 4 (группа), 5
  (подгруппа), 6 (вид).
* `parent` — код родителя; `null` для разделов.
* `is_leaf` — это «лист» иерархии (нет потомков); такие коды реально
  присваивают компаниям.

**Схема `okved_targets.json`:**

```json
{
  "version": "2026-05-06",
  "comment": "Целевые ОКВЭД под сувенирку — список согласован с клиентом",
  "presets": [
    {
      "id": "souvenirs_default",
      "title": "Сувенирка: базовый набор",
      "description": "Компании, которым типично нужны корпоративные подарки и брендирование",
      "codes": []
    }
  ]
}
```

> Поле `codes` — пустой массив **до согласования с клиентом**. Клиент
> присылает свой список, мы заносим его сюда.

### 2.4 Бэкенд

Новый модуль `src/okved/` (название отдельное от `rusprofile/`,
потому что справочник — переиспользуемая вещь, понадобится и для
парсинга Rusprofile, и потенциально для других источников):

```
src/okved/
├── __init__.py
├── loader.py     — load_okved() → читает JSON один раз, кеш в памяти
├── search.py     — search_by_text(query, limit=20) → список совпадений
├── tree.py       — expand_children(code), get_parents(code), is_leaf(code)
└── presets.py    — load_presets(), get_preset(id)
```

**Алгоритм поиска `search_by_text`:**

1. Токенизация запроса: нижний регистр, очистка пунктуации,
   разделение по пробелам.
2. Для каждого кода считаем score:
   * +5 за каждый токен, входящий в `keywords` целиком.
   * +3 за вхождение токена в `description`.
   * +2 за вхождение в официальное `name`.
   * +1 если совпал префикс самого `code` (например, ввели «46»).
3. Сортируем по score, обрезаем по `limit`.
4. Возвращаем `[{code, name, description, score, level}]`.

> На старте берём такой простой ранжер. Если по фидбэку пользователя
> качество поиска недостаточно — возвращаемся и докручиваем (например,
> RapidFuzz для нечёткого совпадения, стемминг через pymorphy2).

### 2.5 Где справочник раздаётся фронтенду

Два варианта, **выбираем №1** для простоты:

**№1. Встроенный JSON в Mini App.** При сборке/деплое копируем
`okved_enriched.json` рядом с `app.js`, фронт грузит его одним fetch'ем.
Размер ~250–400 КБ — нормально для Mini App. Поиск работает на стороне
браузера, без сети.

**№2. HTTP-эндпойнт `/api/okved/search?q=...`.** Сложнее: нужно
поднимать веб-сервер рядом с ботом. На текущем этапе — избыточно.

> Решение: №1. Если потом понадобится — мигрируем на №2 без слома UX.

### 2.6 Что меняется во фронтенде Mini App

В `src/webapp/index.html`:
* Поле `<input id="okved">` заменяется на компонент-сборку:
  * текстовый input для ввода запроса;
  * выпадающий список найденных кодов (показывается, пока пользователь
    печатает; до 20 совпадений);
  * блок выбранных кодов (chips/теги) с крестиком на удаление;
  * чекбокс «включая подгруппы» рядом с каждым выбранным кодом-классом;
  * кнопка/блок «Целевые ОКВЭД под сувенирку» — раскрывает пресет с
    подсветкой того, что уже выбрано.

В `src/webapp/app.js`:
* Загрузка `okved_enriched.json` при старте.
* Реализация поиска (повторяет логику бэкенда, чтобы UX был мгновенным).
* `getFormData()` отдаёт массив кодов в том же формате, что и сейчас —
  бэкенд не трогаем.

### 2.7 Что НЕ меняется

* `src/rusprofile/parser.py`, `src/rusprofile/filters.py`,
  `src/rusprofile/auth.py` — без изменений.
* `src/sheets/client.py`, `src/yandex_maps/*` — без изменений.
* `src/bot/handlers.py` — без изменений (он уже принимает
  `okved` как массив).

## 3. Курируемые пресеты «под сувенирку»

Согласовано два пресета.

### 3.1 «Сувенирка: базовый набор» (`souvenirs_default`)

Целевые отрасли, где сувенирная продукция — типичный товар или
сопутствующая услуга. Это активные «закупщики» брендированной
продукции и тематически смежные с ней.

**Реклама и маркетинг (без узкой наружной рекламы):**

| Код | Название |
|-----|---------|
| `73.11`   | Деятельность рекламных агентств |
| `73.12.1` | Деятельность по продаже места для рекламы в печатных СМИ |
| `73.12.2` | Деятельность по продаже места для рекламы в электронных СМИ |
| `73.12.3` | Деятельность по продаже места для рекламы в Интернет |
| `73.20`   | Исследование конъюнктуры рынка и изучение общественного мнения |
| `70.21`   | Деятельность в сфере связей с общественностью (PR) |
| `70.22`   | Консультирование по вопросам управления (включая маркетинг-консалтинг) |

> Примечание: код `73.12.4` (продажа места для прочей рекламы — в т. ч.
> наружной) **не включён**. Код `73.11` остаётся, потому что под него
> зарегистрировано большинство рекламных агентств полного цикла, и
> ручное отделение «только наружных» из них на стороне ОКВЭД
> невозможно (в ОКВЭД-2 нет отдельного кода «наружная реклама»).

**Канцтовары, ежедневники, корпоративный мерч (опт):**

| Код | Название |
|-----|---------|
| `46.49.3`  | Торговля оптовая писчебумажными и канцелярскими товарами |
| `46.49.4`  | Торговля оптовая книгами, газетами и журналами |
| `46.49.49` | Торговля оптовая прочими непродовольственными потребительскими товарами |
| `46.42`    | Торговля оптовая одеждой и обувью (для брендированной одежды) |

**Автосалоны и автодилеры:**

| Код | Название |
|-----|---------|
| `45.11` | Торговля легковыми автомобилями и легкими автотранспортными средствами |
| `45.19` | Торговля прочими автотранспортными средствами |
| `45.31` | Торговля оптовая автомобильными деталями (крупные дистрибьюторы — типичные клиенты) |

**Рекомендуемые сопутствующие фильтры (`recommended_filters`):**
* `has_phones: true` — без номера обзвон бессмысленен.
* `msp: ["SMALL", "MEDIUM"]` — отсекаем микро-бизнес (ИП-одиночки),
  оставляем малые и средние компании, у которых есть бюджет на сувенирку.

### 3.2 «Корпоративные клиенты (любая отрасль)» (`souvenirs_corporate`)

Под фразу заказчика *«крупные предприятия, оптовая торговля,
производство»*. Эти компании покупают сувенирку для сотрудников,
партнёров и клиентов независимо от отрасли — поэтому ОКВЭД-кодов в
пресете **нет**, отбор идёт по размеру и финансам.

**Пустой `codes`, но проставлены `recommended_filters`:**

| Поле | Значение | Зачем |
|------|----------|-------|
| `msp` | `["MEDIUM"]` | только средние компании из реестра МСП (или вне реестра — это уже крупный бизнес) |
| `has_phones` | `true` | звонить нужно куда-то |
| `finance_revenue_from` | `100000000` | отсекаем мелочь, оставляем компании от 100 млн ₽ выручки |

При клике на этот пресет UI снимает все ОКВЭДы и проставляет только
эти фильтры. Пользователь может потом добавить свой ОКВЭД (например,
конкретную отрасль, на которую сейчас идёт кампания).

### 3.3 Возможное расширение

Схема `okved_targets.json` рассчитана на массив пресетов — позже
легко добавить «новогодние подарки», «брендирование под IT»,
«гостиничный бизнес» и т. п. без изменения кода.

## 4. План реализации по шагам

> Каждый шаг — отдельный коммит/PR, чтобы можно было ревьюить
> поэтапно. Оценка времени — ориентир для планирования; реальные
> сроки зависят от качества справочника при ручной проверке.

### Шаг 1. Сырой справочник ОКВЭД-2 (~0.5 дня)

* Скрипт `scripts/build_okved_raw.py` — скачивает/парсит исходный
  XML/CSV ОКВЭД-2, нормализует в `data/okved/okved_raw.json` по схеме
  `{code, name, level, parent, section, section_name, is_leaf}`.
* Юнит-тест на инвариант: каждый `parent` существует в файле, у
  каждого не-листа есть хотя бы один дочерний код, всего ~2500 записей.
* Коммит: `feat(okved): сырой справочник ОКВЭД-2`.

### Шаг 2. Обогащение «живыми» описаниями (~1–2 дня)

* Claude (вручную, в этом или следующем сеансе) проходит по каждому
  коду уровня 2–4 (классы, подклассы, группы — где обычно ищет
  пользователь) и добавляет `description` + `keywords`. Для кодов
  уровня 5–6 (подгруппы, виды) описание берём от родителя или
  генерим короткое.
* Результат: `data/okved/okved_enriched.json`.
* Ревью: заказчик читает выборочно «живые» описания популярных
  отраслей (торговля, IT, строительство, реклама, общепит) — даёт ОК.
* Коммит: `feat(okved): обогащение справочника живыми описаниями`.

### Шаг 3. Бэкенд-модуль `src/okved/` (~0.5 дня)

* `loader.py`, `search.py`, `tree.py`, `presets.py` со схемой из §2.4.
* Юнит-тесты:
  * «продукты питания» → топ-3 содержит `46.3`/`47.11`;
  * «реклама» → топ-3 содержит `73.1`;
  * `expand_children("46")` возвращает все подкоды `46.x`;
  * `get_parents("46.39.1")` возвращает `["46.39", "46.3", "46", "G"]`.
* Коммит: `feat(okved): модуль поиска и иерархии`.

### Шаг 4. Mini App: автодополнение и chips (~1 день)

* В `src/webapp/index.html` — новая разметка для поля ОКВЭД.
* В `src/webapp/app.js` — загрузка `okved_enriched.json`, поиск,
  выбор/снятие, отрисовка chips, чекбокс «включая подгруппы».
* Стили в `src/webapp/style.css`.
* Ручная проверка: «торговля одеждой» → в списке `46.42`, `47.71`,
  выбираем оба, нажимаем «Запустить парсинг» — в Sheets приходят
  компании именно по этим кодам.
* Коммит: `feat(webapp): автодополнение по справочнику ОКВЭД`.

### Шаг 5. Пресет «под сувенирку» (~0.5 дня)

* Получаем от клиента список кодов, заносим в
  `data/okved/okved_targets.json`.
* В Mini App: кнопка «Целевые ОКВЭД» под полем ОКВЭД, по клику —
  добавляет коды пресета в chips.
* Коммит: `feat(okved): пресет под сувенирную продукцию`.

### Шаг 6. Документация (~0.5 дня)

* `data/okved/README.md` — как обновить справочник, как добавить
  пресет.
* Краткое обновление `README.md` проекта: упоминание справочника.
* `CLAUDE.md` — добавить раздел «Справочник ОКВЭД» (где лежит, кто
  отвечает за обновление).
* Коммит: `docs(okved): инструкция по обновлению справочника`.

**Суммарно:** 4–5 рабочих дней при условии, что список «целевых»
кодов от клиента уже на руках.

## 5. Критерии приёмки

1. В Mini App пользователь, не знающий кодов ОКВЭД, может ввести
   слово «торговля одеждой» и за ≤3 клика собрать корректный набор
   кодов.
2. Выбранные коды через `tg.sendData` уходят на бэкенд массивом и
   корректно отрабатываются существующим парсером Rusprofile (тест
   на 2–3 запросах: результат в Google Sheets > 0 компаний, все с
   подходящим ОКВЭД).
3. Пресет «Сувенирка» добавляет полный согласованный набор за один
   клик, при этом можно снять любой код вручную.
4. Размер `okved_enriched.json` ≤500 КБ (контроль на бесконтрольный
   рост).
5. Юнит-тесты модуля `src/okved/` зелёные.

## 6. Риски и оговорки

* **Качество живых описаний.** Описания пишутся из общих знаний об
  ОКВЭД-2. По специфическим кодам (например, морской промысел) есть
  риск общих формулировок. **Митигация:** ревью клиентом ключевых
  для него отраслей (он читает 30–50 описаний из своей ниши и даёт
  правки).
* **Изменения классификатора.** Росстандарт периодически правит
  ОКВЭД-2 (мелкие изменения). **Митигация:** скрипт
  `build_okved_raw.py` идемпотентен, можно перезапустить при
  следующей официальной редакции; обогащённые описания при этом
  переносятся по `code` как ключу.
* **Размер файла.** При наивной сериализации ~600 КБ. **Митигация:**
  минимизированный JSON (без пробелов), gzip на доставке через
  Telegram Mini App, можно вырезать `level=6` (виды) — пользователь
  обычно ищет на уровне группы.
* **Совпадение кодов с реальным присвоением в Rusprofile.** Если
  пользователь выберет код-раздел (буква `G`), Rusprofile его не
  поймёт. **Митигация:** в UI разрешаем выбирать только коды уровней
  2–6; уровни 1 (разделы) показываем как заголовки группировки.

## 7. Решения по открытым вопросам (согласовано 2026-05-06)

1. **Список целевых ОКВЭД под сувенирку.** Согласован, см. §3.
   Заказчик задал словесно (реклама/маркетинг без наружной;
   опт канцтоваров, ежедневников, мерча; автосалоны/автодилеры;
   крупные корпорации без отраслевой привязки), Claude преобразовал
   в коды ОКВЭД-2.

2. **Какие уровни иерархии разрешать выбирать пользователю.**
   Уровни **2–6** (от класса `XX` до вида `XX.XX.XX`). Пользователю
   важно иметь возможность выбрать максимально узкую подгруппу —
   например, не «вся оптовая торговля 46», а конкретно `46.49.3`
   (канцтовары). При этом на широких уровнях (класс/подкласс)
   доступен чекбокс «включая подгруппы».

3. **`okved_strict`.** Даём пользователю чекбокс
   «Искать также по дополнительным ОКВЭД». **По умолчанию выключен**
   (поведение совпадает с прежним: strict=true, только по основному
   ОКВЭД). Включение чекбокса отключает strict — Rusprofile
   возвращает компании, у которых нужный код есть в любом из ОКВЭД
   (основном или дополнительных).

4. **Поведение при пустом запросе.** Показ при пустом инпуте — не
   показываем ничего (никакого «дерева»). Если пользователь нажмёт
   «Запустить парсинг» с пустым ОКВЭД и без других значащих
   фильтров — кнопка сабмита блокируется и показывается красная
   подсказка: *«Выберите ОКВЭД из справочника или добавьте другие
   фильтры»*. Поле подсвечивается красной рамкой.
